# 送迎順路メーカー

スタッフを車で送るときの順路を決めるアプリ。

**公開URL：** https://ariga0524-tech.github.io/shuttle-router/

URLを開くだけで使えます。ホーム画面に追加しておくとアプリのように起動できます。
`index.html` をダウンロードしてダブルクリックすれば、ネットに繋がっていなくても同じように動きます。

## 使い方

1. 上のURLを開く（または `index.html` をダブルクリック）
2. **今日の条件** … 出発地点と車の台数（1〜3台）を選ぶ
3. **今日の出勤者を選ぶ** … 出勤する人にチェック
4. **送迎場所を決める** … 各人の登録候補から選ぶ。候補外なら「その他」から検索して指定
5. **順路を作成** … 車ごとの回る順番が出る

スマホのホーム画面に追加しておくとアプリのように使えます。

## 画面の構成

ふだんの担当者に見えるのは3つだけです。

- **送迎を組む** … その日の出勤者を選んで順路を作る
- **スタッフ・場所** … スタッフと送迎場所の登録
- **パスワード** … 担当者どうしで使うパスワードの設定・変更

そのほかの設定は**管理画面**に隠してあります（下記）。

## できること

- 車1台につき最大4人（定員は管理画面で変更可）。**誰をどの車に乗せるかは自動で最適化**します
- **人数が定員を超えるときは、車が戻って積み直す「便」に自動で分けます**
  （例：13人・1台なら4便）。どの人を何便目にするかも最適化の対象です
- 「全員を降ろし終わるまで」と「出発地点に戻るまで」の両方の時間を表示
- 順番の入れ替え（↑↓）、別の車への移動、当日キャンセル（×）を手で調整でき、都度時間が再計算されます
- 「Googleマップで開く」でそのままカーナビに流せます
- 「コピー」でLINE等に貼れるテキストを出力

## 送迎場所の登録

「スタッフ・場所」タブで場所を追加するとき、住所を入力して「検索」を押すだけで登録できます。
緯度経度を自分で調べる必要はありません。

- 住所（「東京都新宿区西新宿2-8-1」など）でも、駅名や施設名（「中野坂上駅」など）でも検索できます
- 見つかった場所がプレビューに出るので、確認してから保存してください
- 見つからない場合や、ピンポイントで指定したい場合は「座標を直接入力する」を開き、
  Googleマップで地点を右クリック →「座標をコピー」で出た値を貼り付けられます（これまで通りの方法）
- 名前だけを編集する場合、住所を再検索しなければ元の場所は変わりません

検索には [OpenStreetMap Nominatim](https://nominatim.openstreetmap.org/) という無料の住所検索サービスを使っています。
APIキーの登録や費用は一切かかりません。

## 管理画面

**タイトル「送迎順路メーカー」を5回続けてタップ（クリック）**すると開きます。
パスワードを設定してある場合は、**マスターコードを知っている人しか入れません**。
ふだんの担当者には存在が見えないので、触られて壊れる心配がありません。

管理者と担当者の役割は分けてあります。

| | 管理者 | 担当者 |
|---|---|---|
| パスワードの設定・変更 | ✕（不要） | **○**（パスワードタブから） |
| マスターコードでの管理画面アクセス | ○ | ✕（存在も見えない） |
| マスターコードの変更 | ○ | ✕ |
| 保護の解除 | ○ | ✕ |
| Google連携・共有・データ入出力 | ○ | ✕ |

**管理者は担当者のパスワードを一切知りません。** パスワードの設定・変更はすべて
「パスワード」タブから担当者自身が行います。管理者はアプリに焼き込まれた
固定のマスターコードで、担当者が何をパスワードにしていてもいつでも入れます。

管理画面にあるもの：

- 順路の計算（最適化の基準・定員・停車時間・推定に使う速度と道のり係数）
- Googleマップの実測所要時間（APIキー、取り直し）
- みんなで共有する（Firebase）
- パスワードとマスターコード
- データの保存・移行（引っ越しリンク、JSON入出力、初期化）

閉じるときは右上の「アプリに戻る」を押します。

## 所要時間をGoogleの実測にする

管理画面でAPIキーを一度入れるだけです。**担当者は何も意識しません。**

- 順路を作るとき、その日に使う地点の実測値が足りなければ自動で取りに行きます
- 取得した所要時間は保存され、共有中ならほかの担当者にも自動で配られます
- 場所を追加したときも、その区間だけ自動で取りに行きます
- キーを入れなければ、直線距離からの概算で動きます（中野駅からの主要駅で実測との平均誤差3分）

### 費用

課金対象は「取りに行った区間の数」だけです。1日に使う地点が5か所なら1回25要素程度。
Routes API の無料枠（月1万要素前後）には遠く届きません。**実質0円です。**

一度取得した区間は保存して使い回すので、毎日呼び直すことはありません。

⚠️ Google Cloud コンソールで、キーに①ウェブサイトの制限 ②Routes API のみ許可
③1日の割り当て上限、を必ず設定してください。これで万一漏れても課金事故は起きません。

## みんなで共有する（担当者が日によって変わる場合）

名簿・場所・設定を全員で共有できます。誰が編集しても、ほかの担当者のアプリに反映されます。
**暗号化したまま預けるので、保管先（Google）にも中身は読めません。**

### 最初の1人がやること

1. [Firebase コンソール](https://console.firebase.google.com/)で「プロジェクトを追加」
2. 「Firestore Database」→「データベースの作成」→ 本番環境モード
3. 「Authentication」→「始める」→「匿名」を有効にする
4. Firestore の「ルール」を次に置き換えて公開

   ```
   rules_version = '2';
   service cloud.firestore {
     match /databases/{database}/documents {
       match /shuttle/{doc} {
         allow read, write: if request.auth != null;
       }
     }
   }
   ```
5. 「プロジェクトの設定」→ マイアプリ →「ウェブ」を追加。表示される設定を控える
6. アプリの設定タブで**先にパスワードを設定**し、続いて上の設定を貼って「共有を始める」

### あとから参加する人

設定タブで Firebase の設定を貼り、「共有を始める」を押すだけです。
共有中のパスワード（またはマスターコード）を聞かれるので、それを入れれば名簿が入ります。
**パスワードを先に設定する必要はありません。**

すでにアプリを使ったことがある端末なら、`shuttle-router.share` の設定を入れて開き直すだけでも参加できます。

### 費用

Firebase の無料枠は 1日あたり読み取り5万回・書き込み2万回です。
4人が1日に何度か編集する程度では桁が2つ足りないので、**費用はかかりません。**

### 同期のタイミング

- 名簿を変えると自動で送られます
- アプリに戻ってきたとき（別のタブから切り替えたときなど）に自動で取りに行きます
- 設定タブの「今すぐ同期」でいつでも手動で合わせられます
- 同じタイミングで別の人が編集していた場合は、どちらを残すか確認が出ます

### 注意

- 全員が**同じパスワード**を使います。個人ごとのアカウントではありません
- 誰かがパスワードを変えると、ほかの担当者は次から新しいパスワードが必要になります
  （マスターコードは変わりません）
- 共有をやめても、名簿はその端末に残ります

## パスワードとマスターコード

管理画面の「パスワードを設定」で、名簿を暗号化して保存できます。
設定するとアプリを開くたびにパスワードを聞くようになります。
共有を使う場合は、このパスワードを担当者全員で共有します。

管理者用の**マスターコード**が、パスワードとは別に最初から効きます。
インストール直後から使える固定の値で、担当者には一切見えません。
管理画面から作り直すこともできます（12文字以上、または自動生成）。
次の2つに使います。

- パスワードを忘れたときに名簿を開く
- **管理画面に入る**（タイトル5回タップのあとに聞かれます）

### 仕組み

名簿はランダムな「データ鍵」で暗号化し、そのデータ鍵を
①パスワード ②マスターコード の2通りで包んで保存します。
どちらからでも同じデータ鍵が取り出せるため、

- 管理者はいつでも開ける
- パスワードを変えてもマスターコードは有効なまま。名簿を暗号化し直す必要もない
- マスターコードだけを作り直すこともできる（古いコードは無効になる）

暗号は AES-GCM 256bit、鍵の導出は PBKDF2-SHA256 31万回です。
保存データそのものを暗号化するので、ブラウザの保存領域を直接覗かれても、
パスワードなしでは名前も駅名も読めません。

### 注意

- **パスワードとマスターコードの両方を失うと、名簿は取り出せません。**
  マスターコードは控えて、アプリの外（パスワード管理ツールなど）に保管してください
- マスターコードを失うと、名簿は開けても**管理画面に入れなくなります**
- 担当者が入れ替わったらパスワードを変えてください（マスターコードは変わりません）。
  変更は担当者自身が「パスワード」タブから行えます
- パスワードを変更するときは、いまのパスワード（またはマスターコード）の入力が必要です
- アプリのコード自体は誰でも読めます（公開URLのため）。安全性はパスワードの強さに依存します。
  8文字以上・英数字混在にしてください
- URLを知られただけでは名簿は漏れません。名簿はアプリのコードには含まれないためです

## データの保存場所と、別の端末への移し方

スタッフ・場所・設定は、開いた端末のブラウザに保存されます。サーバーには何も送られません。

別の端末に移すときは、設定タブの**「別の端末に移すリンクを作る」**を押してください。
名簿がURLの `#` 以降に畳み込まれたリンクができるので、LINEやメールで自分宛てに送り、
移したい端末で開けば取り込めます。Googleの実測所要時間も、リンクに収まる長さなら一緒に運びます。

**APIキーは、リンクが暗号化されるとき（パスワード設定済みのとき）だけ一緒に運びます。**
保護していない状態のリンクには含まれません。

`#` より後ろはサーバーに送信されない仕様なので、リンクを経由しても名簿が外部に渡ることはありません。
ただしリンク自体に名簿が入っているため、送り先は間違えないでください。

バックアップが欲しい場合は、設定タブの「JSONで書き出す・読み込む」も使えます。

## 順路の決め方

同じ場所の人は同じ車にまとまります（定員を超える場合のみ分割）。

**1便で運びきれる場合**（人数 ≤ 台数×定員）：停車地点の組み合わせごとに最短の回り方を求め、
集合分割の動的計画法で「いちばん遅く終わる車の時間」が最小になる割り当てを選びます。

**運びきれない場合**：車が出発地点に戻って積み直す「便」に分けます。
便の分け方・車への割り振り・車内の順番を、まとめて最適化します。
最終便だけは帰りを数えないため、帰り道の長い方面が最後に回るよう自動で調整されます。
車どうしは待ち合わせないので、全体の所要時間は「いちばん遅く終わる車の合計」です。

停車地点が13か所までは厳密な最適解を出します（総当たりと照合して確認済み）。
それを超える場合は、方面ごとにまとめてから空いている車へ順に積む近似で組みます。
